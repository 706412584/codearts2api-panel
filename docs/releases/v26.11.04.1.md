本次补齐图片请求处理，新增按需图片分析模式；账号页自动刷新池状态，运行日志增加排队耗时、首字时间和失败原因，模型目录改为直接展示账号实际上游目录。

### 新增

- 聊天请求体上限改为可配置的 `max_body_mb`，默认 32MB；超限请求明确返回 413。凭据导入仍独立限制为 8MB。
- 内联 PNG/JPEG 支持按需缩图，默认在请求体超过 4MB 或图片超预算时触发，目标为单张 2MB、合计 4MB、最长边 2048 像素、JPEG 质量 85。小图保持原样，WebP/GIF 和远程图片不参与缩图。
- 默认 `image_handling=bridge`：给纯文本模型的内联图片先交视觉模型转述，再交原模型回答；默认使用 `Qwen3-VL-235B`，最多处理 8 张图，总预算 90 秒。转述结果可缓存；超出数量或转述失败时保留全部原图，继续按原请求处理。
- 新增 `image_handling=analyze`：在目录明确声明模型不支持图片时，把图片换成占位符并注入 `analyze_image` 工具，由主模型决定看哪张图、问什么；网关执行视觉分析后回灌结果，最多 4 轮。可在配置页 Raw JSON 中启用，主模型需支持工具调用。带图请求会先聚合，再为流式客户端以 SSE 回放；纯文本流式请求保持直通。图片暂存进程内 30 分钟，重启后不保留。
- `image_handling=passthrough` 关闭桥接和按需分析；如果账号目录明确声明目标模型不支持图片，带图请求会在本地返回 400 并列出可用视觉模型。
- 服务配置页新增请求体、图片压缩、视觉转述表单，保存后热生效；模型目录增加“外置视觉理解”提示，区分原生视觉能力和转述能力。
- 账号页可见且未搜索、未打开对话框时，每 10 秒只刷新账号池概览；切换到其他页面、浏览器进入后台或已有刷新请求时暂停。
- 最近请求日志新增 TTFT、缓存 Token、总 Token 和排队耗时；失败请求按底层原因显示徽标，并提供带条数的“成功 / 失败 / 异常”筛选。条数只统计当前已取回的记录。

### 修复与调整

- 请求参数错误、非多模态输入、上下文超长和客户端取消不再误伤健康账号；客户端断开时停止等待上游，视觉子请求也遵守取消和图片处理策略。
- 移除模型可用性探测及其结果缓存，不再为探测额外发送聊天请求；模型列表以账号实际目录为准，上下文长度缺失时显示“未知”。
- 上游聊天请求的身份、追踪、会话及模型请求头对齐官方 CodeArts Agent CLI；同一聊天继续使用稳定的会话标识。

### 使用与升级

从本次 Release 下载对应平台压缩包，解压后运行 `codearts2api-panel.exe`（Windows）或 `./codearts2api-panel`（Linux）。首次运行会创建包含独立随机密钥的 `config.json`，在 `http://127.0.0.1:7866/panel` 使用 `admin_key` 登录。

升级前停止旧进程并备份 `config.json`、`auths/` 和 `data/`，然后仅替换程序文件；不要用示例配置覆盖已有配置。安装包不含真实配置或账号凭据。

旧配置缺少新字段时，图片缩图和视觉转述默认开启，图片处理模式默认为 `bridge`。每张未命中缓存的转述图片会额外消耗一次视觉模型调用额度并增加等待时间；精细颜色和布局问题仍建议直接使用视觉模型。可用 `vision_bridge.enabled=false` 关闭转述、`image_shrink.enabled=false` 关闭缩图；`analyze` 模式需另行在 Raw JSON 中设置。
